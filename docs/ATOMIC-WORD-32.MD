# H428 — ESP-IDF Xtensa AtomicWord32 provider

The existing EDP-Platform \`AtomicWord32\` Composition contract requires exactly four bytes of truly lock-free storage and relaxed/acquire loads, relaxed/release stores and acquire-release compare/exchange. Portable std::atomic<uint32_t> correctly rejects the ESP32-S3 cross-compiler because its \`is_always_lock_free\` guarantee is false. This new **explicitly included**, target-limited \`src/concurrency/AtomicWord32Provider.hpp\` instead uses aligned naturally atomic 32-bit Xtensa loads/stores with Xtensa \`memw\` barriers and Espressif's \`esp_cpu_compare_and_set\` atomic CAS implementation. No spinlock, task, heap or disabling interrupts is introduced. It is not automatically included from the umbrella, retaining the existing RISC-V platform compatibility; unsupported MCU families cause a deliberate compile error rather than falsely claiming lock-free metadata.

**Actual physical evidence:** ESP32-S3 D board (eFuse 28:84:85:43:a7:04) built with ESP-IDF/PioArduino \`20261019T125101-175217c8\` PASS, image hash flash \`20261019T125154-3b8faa7a\` PASS, 2 independent pinned FreeRTOS tasks on cores0 and1 each ran 25,000 CAS increments against one four-byte provider word (50,000 exactly), physical UART \`20261019T125233-eea12d9f\` PASS. Real production ClockCoordinator in opt-in certified guard mode on S3 also refused Root promotion before Clock Observe, H414 durable receiver NVS remained term0/root0. Earlier ESP32-S3 build with unsupported portable provider failed \`20261019T123842-8f3f66e7\`; it was not used on-device. The same source was cross-built for ESP32 WROOM \`20261019T125640-87a64dd9\` PASS, but NOT separately flashed/stressed on WROOM.

Evidence does not establish external time authenticity, P256 quorum certificate or H414 positive authority; H405 and independent Root0 are unchanged. No RF session or NVS credentials were replaced. Future ESP32-C3/RISC-V target requires its own reviewed provider and tests, not this Xtensa-only code. All library versions remain 0.1.0.
